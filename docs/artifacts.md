## Regeneration Map

Use this order when rebuilding the project from source:

| Step | Command | Produces |
| --- | --- | --- |
| 1 | External arXiv metadata download | `data/raw/arxiv-metadata-oai-snapshot.json` |
| 2 | Run extraction / EDA notebook workflow | `data/processed/arxiv_cs_full.parquet` |
| 3 | Run cleaning notebook | `data/processed/arxiv_cs_clean.parquet` |
| 4 | Run V1 baseline notebook | `models/v1_tfidf_vectorizer.pkl`, `models/v1_logreg.pkl`, `models/v1_label_encoder.pkl`, `models/v1_metrics.json` |
| 5 | `python scripts/prepare_multilabel_data.py` | `train.parquet`, `val.parquet`, `test.parquet`, `v3_categories.json`, `v3_pos_weights.npy` |
| 6 | `python scripts/embed_papers.py` | `v3_specter2_embeddings.npy`, `v3_papers_meta.parquet` |
| 7 | `python scripts/build_faiss_index.py` | `v3_faiss.index` |
| 8 | `python scripts/train_lora_classifier.py` | LoRA checkpoints, metrics history, threshold sweeps |

## Why Artifacts Are Ignored

The project uses reproducible scripts and notebooks for generated assets, but the assets themselves are too large for a clean portfolio repository. Keeping them ignored prevents accidental multi-GB commits and makes the repository reviewable on GitHub.

The tradeoff is that a fresh clone is inspectable immediately but not fully runnable until local artifacts are restored or regenerated.
